# Specifications: WORKFLOW\n\n## Table of Contents\n- [Overview](#overview)\n- [Architecture](#architecture)\n- [Execution Model](#execution-model)\n- [Scheduling Model](#scheduling-model)\n- [Orchestration Model](#orchestration-model)\n- [Catalog](#catalog)\n\n## Overview\n\nThe Workflow specification defines the declarative orchestration language and execution framework of Atlas. Workflow is the central abstraction through which all Atlas subsystems coordinate their activities, manage their lifecycles, and achieve their objectives.\n\nWorkflow is NOT scripting. Workflow is NOT automation. Workflow is NOT macros. Workflow is NOT programming. Workflow is the declarative orchestration language of Atlas.\n\n## Architecture\n\n`mermaid\ngraph TB\n    subgraph Workflow[Workflow Layer]\n        Lang[Workflow Language]\n        Graph[Workflow outcomes every time.\n- **Resumable**: Pausable and resumable from any checkpoint.\n- **Observable**: Every state change emits an observable event.\n- **Debuggable**: Every execution point is inspectable.\n\n## Scheduling Model\n\nThe Workflow Scheduler determines WHEN and WHERE each node is executed, considering dependencies, resources, priorities, budgets, and constraints.\n\n## Orchestration Model\n\nOrchestration coordinates multiple nodes, subsystems, and resources through data flow, control flow, event flow, resource flow, and state flow.\n\n## Relation to Runtime\n\nWorkflow instances are managed as runtime entities. Workflow nodes are registered as runtime services. Workflow events flow through the runtime event bus. Workflow state is persisted through the runtime state store.\n\n## Relation to Plugin\n\nPlugins register node types that become available in workflow graphs. Plugin capabilities are discovered and used by workflow nodes. Workflow nodes inherit plugin sandboxing and permission policies.\n\n## Relation to Storage\n\nWorkflow nodes perform storage operations (read, write, query, delete). Storage operations within workflows are transactional and respect domain boundaries.\n\n## Relation to Vision\n\nVision nodes execute vision operations (frame capture, OCR, detection, segmentation). Vision results propagate through the data flow model.\n\n## Relation to AI\n\nAI nodes execute AI model inference or agent operations. AI operations are bounded by execution budgets and timeouts.\n\n## Relation to IPC\n\nIPC nodes coordinate across process boundaries. IPC messages follow the common event model.\n\n## Relation to Knowledge\n\nWorkflow nodes access knowledge packs for context and reference. Knowledge context propagates through workflow execution.\n\n## Relation to Marketplace\n\nWorkflow packages are distributed through the marketplace. Marketplace version resolution applies to workflow dependencies.\n\n## Catalog\n\n| Document | Description |\n|---|---|\n| [workflow-actions](catalog/workflow-actions.md) | Action type catalog |\n|
